# 晨报模型评测与阅读结构（2026-09-22）

本次改进针对读者必须离开晨报自行查分、以及多处结论重复的问题。现行工作流以 `skills/ai-daily-report/SKILL.md` 的 3b-1 / 3b-2 为准。

## 已确认的问题

- 9 月 22 日 Grok 正文只给出厂商三项分数和独立两个指数，未解释评测含义、对照、推理档位与运行框架。其独立评测页实际上公开了编码子项、退步项与输出 Token 消耗。
- MiMo 正文只给出综合指数 46 和模糊的“前列”判断，未提取官方模型卡的完整分项；Pro 与 Flash 也未分别比较。
- 9 月 21 日 Step 5 已列多个分数，但读者仍不知道各项目测什么、对照如何；普通非 major 模型条目没有能力详解入口。
- 模板把混合厂商/独立评测的 `expanded.benchmarks` 统一标为“官方基准”，容易混淆证据性质。
- 生态与方法论排在硬数据、决策之前；同一试点判断又在观察、雷达、实验、建议中重复。原始数组引用显示在读者界面。
- “无昨日快照”被过度应用：它限制跨日榜单变化，不能阻止引用评测方公开的新旧版本对照。
- 今天的行动建议把两款模型都描述为可在已有 Coding 席位试验，但接入证据只支持 Grok；MiMo 应单独确认 API/部署路线。

## 当前契约

新日报用 `version: 1.2`，历史 `1.0/1.1` 可读取和重渲染。1.2 继承 1.1 要求每条模型信息明确交代能力评测状态，并要求顶层 `reading_guide`（可为空）。纯调价等事件可说明“不适用”，证据不足可说明缺口，不能伪造分数。

能力卡分来源和测试条件列出：评测名称与版本、中文解释、准确型号/档位、数值和单位、对照、解读。厂商自报、独立评测与团队实测明确区分。缺测试配置、样本量或误差范围时直接说明，不能靠一个总分推导生产效果。

正文按以下顺序阅读，字段名和锚点保持稳定，目录及正文编号一致：

1. 模型动态
2. Coding Agent
3. 通用与办公 Agent
4. 政策与风险观察
5. 硬数据信号
6. 跨条目模式
7. 决策雷达
8. 落地建议
9. 建议实验
10. 生态实践
11. 方法论雷达
12. 待核实

开头用“今日核心判断”回答能力定位、关键对照、成本取舍、适用任务与主要边界；不能只写“值得看、仍需验证”。优势有证据时明确肯定，证据不足时具体说明，不把客观写成含糊。模型的详细分数留在能力卡；硬数据节保留快照/变化审计摘要。行动描述投入和验收，实验负责步骤，雷达说明决策门槛，模式负责跨事件的新判断。

能力和经济性同时比较：先核对评测版本、模型变体、档位及框架，再区分 API 单价、评测任务费用、实际成功成本、订阅和自部署成本。跨页面的对照与定价来源放入 `supporting_sources`，与主来源一起接受精确 URL 抓取记录校验。报告以 AI 编辑判断给出建议，不用固定评分函数生成“性价比”排名。

HTML 与钉钉共享语义标题：报告 H1、栏目 H2、模型/事件 H3、能力评测 H4、评测分组 H5。模型导读链接显示“查看详评”，普通产品和风险显示“查看详情”，在线版不追加重复新闻标题。钉钉发布时，除全文回读外，还必须用 `validate_dingtalk.py` 将原生块的完整标题大纲与最终 HTML 比对；修复今天文档不能代替未来发布验收。

## 校验与边界

### 独立专题的当前契约

重大事件的补证、expanded 和事件追踪继续执行；独立专题仅在解决具体选择问题、增加晨报之外的实质分析时生成。AI 先按 [专题研究工作流](../skills/ai-daily-report/workflows/deep-dive-research.md) 复核，再将 slug 放入日报顶层 `deep_dive_refs`；没有成熟专题写 `[]`，历史日报省略该字段按空处理。runner 仅渲染和投递清单内文件，不扫描草稿，也不从事件标签推导清单。

专题 1.1 包含明确问题、结论、证据对照、场景与推断边界、成本约束、公开证据缺口及业务验证问题。字段与引用闭环由程序校验；研究增量、来源可信度和结论成立与否由 AI 判断，不用机械分数代替。历史 1.0 七节模板只用于历史重渲染，新投递清单仅接受 1.1。每天晨报的邮件和钉钉全文同步照常进行。

- schema 拒绝 1.1/1.2 模型条目缺能力卡、`assessed` 空表、评测关键字段缺失、证据不足却不写缺口。
- finalize 检查能力卡每组来源都有精确 URL 的成功抓取记录，并检查核验时间、导读引用。
- 测试覆盖新格式、老格式兼容、负分/零分、转义与链接，以及目录/正文顺序。
- 来源记录校验只能证明“记录关联完整”，不能自动证明分数抄录准确、配置可比或编辑结论成立；这些由 AI 读原始表格与脚注完成。
- 本次生成 `reports/reviews/2026-09-22/report.html` 作为独立预览。它标注补证时间，不作为原晨间已知信息，不覆盖发送记录或原归档。
- 周报新格式为 1.1；聚合时读取日报能力卡，保留可比条件与证据分层。旧周报 1.0 保持可读。


## 通用与办公 Agent 的当前契约（2026-09-28）

执行 [专门编辑工作流](../skills/ai-daily-report/workflows/general-agent-editorial.md)。产品身份、证据强度、栏目归属和行动资格分别判断。通用产品卡回答工作任务、变化、能力形态、使用条件与实际影响；政策风险卡回答事件状态、适用范围和证据边界。风险可以引用到决策层，不能为了引用资格伪装成产品。

新日报/台账/周报版本分别为 1.2/1.1/1.1，初始化锁定版本。完整保存工具返回，分块提供给编辑，按文件与片段重算审查覆盖；脚本不证明语义理解。selected 与正文双向检查，直接证据与背景分开，所有行动依据分别受行动资格约束。action_delta 由 AI 对照前期判断新增投入；产品稀薄日限制保持不变。

新周报通用栏使用 typed items，旧双数组仅在历史分支读取。跨版本归纳保留原引用，跨栏目说明 origin_classification_note。工作流允许产品、风险、模式、实验和行动为空，禁止为填栏目制造事件或投入。

## 真实重跑后的阅读与展示验收

日报coverage_summary由编辑合并来源缺口，不将逐次抓取reason自动铺入正文。空栏目保留empty_message。同一HTML转出的全文Markdown也必须保留这两类说明。

证据阅读使用evidence.py逐块read，观察完整工具返回后再ack；预生成的全量回执不能证明实际提供。两层工具输出任一层截断都必须补读遗漏范围。机器重算只证明实际传入输出与规范内容一致，不证明模型理解。

同日重跑的delivery_result.json记录当前HTML与已发送HTML的哈希及本轮结果，旧发送记录没有哈希则明确未知。重复跳过与新稿已发送分别报告；钉钉按对应source_html_sha256核验。
